**Goal:** Add a required `python-wsl` CI leg that exercises the setup-script `.sh` tests + the `bin/alfred-setup.ps1`→`wsl bash` forwarding **from WSL2, over the Windows-side checkout (`/mnt/c`)**, so Windows-via-WSL idiosyncrasies (CRLF, `/mnt/c` interop, the `.ps1` handoff) are caught in CI.

Promoted to a required status check immediately after merge.

**Tech Stack:** GitHub Actions, `Vampire/setup-wsl`, WSL2 Ubuntu-24.04, `uv`, pytest, bash, PowerShell.

**Spec:** `docs/superpowers/specs/2026-07-24-wsl2-ci-leg-design.md`.

### Task 1: `.gitattributes` (LF for shell scripts) + portable LF-guard test

**Files:**

- Create: `.gitattributes`
- Create: `tests/unit/meta/test_shell_scripts_lf.py`

**Interfaces:**

- Produces: the invariant "every tracked `*.sh` is stored LF-only" — Task 2's WSL leg depends on it (a CRLF `.sh` breaks `bash` under WSL over `/mnt/c`).

- [ ] **Step 1: Write the failing LF-guard test.**

```python
"""#496: every tracked shell script is LF-only. A CRLF `.sh` breaks `bash` under WSL
(over /mnt/c on a Windows checkout) with a `\\r`/bad-interpreter error. .gitattributes
`eol=lf` enforces it on checkout; this test guards the invariant on every OS leg."""
from __future__ import annotations
import subprocess
from pathlib import Path

def test_all_shell_scripts_are_lf() -> None:
    tracked = subprocess.run(
        ["git", "ls-files", "*.sh", "bin/*"], capture_output=True, text=True, check=True
    ).stdout.split()
    offenders = []
    for rel in tracked:
        p = Path(rel)
        if not p.is_file():
            continue
        head = p.read_bytes()[:4096]
        # only shell scripts (skip .ps1 etc.); a .sh or a shebang-bash file
        if rel.endswith(".sh") or head.startswith(b"#!") and b"sh" in head.split(b"\n", 1)[0]:
            if b"\r\n" in p.read_bytes():
                offenders.append(rel)
    assert not offenders, f"CRLF found in shell scripts (must be LF): {offenders}"
```

- [ ] **Step 2: Run — expect PASS** (repo content is already LF on a unix checkout), so instead prove non-vacuity: temporarily write a CRLF into a scratch `.sh` under `tmp` and assert the *helper* flags it, OR run with a deliberate CRLF injected into a tracked file in a throwaway commit and confirm RED. Document the RED evidence. `uv run pytest tests/unit/meta/test_shell_scripts_lf.py -v`.

- [ ] **Step 3: Create `.gitattributes`.**

```gitattributes
# #496: normalize line endings so a Windows checkout keeps shell scripts LF (a CRLF
# `.sh` breaks bash under WSL). Default: let git decide text vs binary.
* text=auto

# Shell scripts + the bin/ launchers MUST be LF on every platform (run under bash/WSL).
*.sh text eol=lf
bin/alfred-setup.sh text eol=lf
bin/alfred-plugin-launcher.sh text eol=lf
bin/alfred-state-git-seed.sh text eol=lf

# PowerShell is native-Windows — keep CRLF.
*.ps1 text eol=crlf
```

(Grep `bin/` + the repo for other `*.sh` and add them, or rely on the `*.sh` glob; confirm no `.sh` lives outside the glob.)

- [ ] **Step 4: Renormalize + verify.** Run: `git add --renormalize . && git status --short`. Expected: no `.sh` shows a modification (they were already LF); the `.gitattributes` is the only add. Run the guard test → PASS.

### Task 2: The `python-wsl` CI job

**Files:**

- Modify: `.github/workflows/ci.yml` (add the `python-wsl` job)

**Interfaces:**

- Consumes: Task 1's LF invariant. Produces: a CI check named `Python WSL` (or `python-wsl (ubuntu-24.04)` — confirm the exact rendered context name; Task 3's promotion needs it verbatim).

- [ ] **Step 1: Pin the action.** Resolve the latest `Vampire/setup-wsl` release + its commit SHA. Record `Vampire/setup-wsl@<sha> # vX.Y.Z`. (Verify it supports `distribution: Ubuntu-24.04`; if not, use the newest Ubuntu it offers and note it.)

- [ ] **Step 2: Add the `python-wsl` job to `ci.yml`** (near `python-cross-os`). Skeleton:

```yaml
  python-wsl:
    # #496: the ONLY leg that exercises the supported Windows path — repo on the Windows
    # filesystem, setup scripts run FROM WSL over /mnt/c. Catches CRLF / interop / the
    # bin/alfred-setup.ps1 -> `wsl bash` handoff that neither python-cross-os (native) nor
    # the ubuntu legs see. Scoped to the setup-script + .ps1 surface only (WSL ~= Ubuntu
    # for pure Python — already covered by the `python` job).
    name: Python WSL (ubuntu-24.04)
    runs-on: windows-latest
    timeout-minutes: 30
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v7.0.0
        with:
          persist-credentials: false
      - name: Provision WSL2 (Ubuntu-24.04)
        uses: Vampire/setup-wsl@<sha> # vX.Y.Z
        with:
          distribution: Ubuntu-24.04
      - name: uv + Python + deps INSIDE WSL, over /mnt/c
        shell: wsl-bash {0}
        run: |
          set -euo pipefail
          curl -LsSf https://astral.sh/uv/install.sh | sh
          export PATH="$HOME/.local/bin:$PATH"
          # repo is at the Windows-side checkout via /mnt/c (the interop we test); keep the
          # venv WSL-native to avoid /mnt/c I/O cost — the repo path is what matters.
          export UV_PROJECT_ENVIRONMENT="$HOME/.wslvenv"
          uv python install 3.14
          uv sync --frozen --dev
      - name: Setup-script .sh tests UNDER WSL (over /mnt/c)
        shell: wsl-bash {0}
        run: |
          set -euo pipefail
          export PATH="$HOME/.local/bin:$PATH"
          export UV_PROJECT_ENVIRONMENT="$HOME/.wslvenv"
          # win32 skips DON'T fire under WSL (sys.platform == "linux") -> these run for real.
          uv run pytest tests/unit/test_setup_script_*.py -v
      - name: Line-ending guard (no CRLF in .sh as WSL sees them)
        shell: wsl-bash {0}
        run: |
          set -euo pipefail
          if grep -lrP '\r$' bin/*.sh 2>/dev/null; then
            echo "::error::CRLF found in a .sh under WSL — the .gitattributes LF rule regressed."; exit 1
          fi
      - name: .ps1 -> wsl bash forwarding smoke
        shell: pwsh
        run: |
          $ErrorActionPreference = "Stop"
          & bin/alfred-setup.ps1 --dry-run
          if ($LASTEXITCODE -ne 0) { throw "alfred-setup.ps1 --dry-run failed (exit $LASTEXITCODE)" }
```

(Confirm the `Vampire/setup-wsl` shell handle — it's `wsl-bash {0}` when the action sets a default shell; adjust to the action's documented shell name. Confirm `bin/alfred-setup.sh --dry-run` exits 0 without a Docker daemon — it's a prereq-only check per `setup.sh:6,81`; if `--dry-run` still probes Docker, gate the smoke or use the deepest no-op the script supports.)
