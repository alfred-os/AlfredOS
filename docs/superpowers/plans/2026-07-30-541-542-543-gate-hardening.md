# #541 + #542 + #543 — Gate Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the three #537 follow-ups the PR #540 review fleet found — make the two new gate surfaces non-silently-removable (#541), stop a pathological source file from aborting the `check_tag_t3` scan under a mislabelled exit code (#542), and put the two gate-enforcing scripts that are measured-but-ungated under their own 100% gates behind an allow-list census (#543).

**Architecture:** Every fix follows the same rule the three issues share: *a gate must fail loudly when it is weakened, and no single deletion may disarm it.* So each surface gets **two independent layers** — a runtime floor that reds inside an already-required check, plus a static pin naming the surface. Where a claim in an issue could not be reproduced by execution, this plan says so and closes the **class** by default-deny rather than enumerating names (`domain_enumerate_vs_default_deny`).

**Tech Stack:** Python 3.14.6 (stdlib `ast`, `subprocess`, `pathlib`), pytest, `coverage`/`pytest-cov`, PyYAML, GitHub Actions, GNU Make.

### #542 claims — one confirmed, one **refuted** by execution

Probed on the repo's own CPython **3.14.6** (`.venv/bin/python3`, `recursionlimit=1000`):

| Input | Result |
| --- | --- |
| `"not " * 20000 + "x"` | **`MemoryError: Parser stack overflowed`** — confirmed, not a `SyntaxError` |
| `"-" * 20000 + "x"` | `MemoryError` (same) |
| `"1 if a else " * 20000 + "2"` | `MemoryError` (same) |
| `"lambda: " * 5000 + "1"` | `MemoryError` (same) |
| `"a" + " ** a" * 20000` | `MemoryError` (same) |
| **`"x = " + "+".join(["1"]*50000)`** (the issue's "long binop chain") | **parses fine** — no error |
| `"a" + ".b" * 50000` | parses fine, `ast.walk` visits 100 006 nodes, no error |
| `"a" + "[0]" * 20000` / `"()" * 20000` / `" or ".join(["a"]*50000)` / 100 000-element tuple | all parse fine |
| `"(" * 200000 …` / `"[" * 100000 …` | `SyntaxError: too many nested parentheses` — **already handled** |
| `Path("foo\x00bar.py").read_text()` | **`ValueError: embedded null byte`** — confirmed, and **not** an `OSError` |
| `ast.parse("x = 1\x00\n")` | `SyntaxError` with `lineno=None` — already handled by the existing `or 1` |

**Conclusion: `RecursionError` is not reachable from `_scan_text` on CPython 3.14.6.** Eleven nesting shapes were probed; the parser converts deep nesting into `MemoryError` (parser stack) or `SyntaxError` (bracket-nesting limit), `ast.walk` is iterative, and every helper in `check_tag_t3.py` (`_call_name`, `_arg_name`, `_is_tag_t3_call`, `_is_cast_tagged_content_call`, `_is_tagged_content_t3_subscript_call`) is a flat `isinstance` check with no recursion.

**Therefore Task 5 does NOT add a named `except RecursionError` arm.** A named arm for an unreachable exception is either an uncoverable line (which breaks the 100% gate) or a line covered only by a fabricated `raise RecursionError` — a test that proves nothing and would have to `monkeypatch` `ast.parse`, which the brief explicitly forbids. Instead the arm is **default-deny over the class**: catch what `ast.parse` can raise *other than* `SyntaxError`, so `RecursionError` is covered without being named, along with anything a future CPython adds. This is `domain_enumerate_vs_default_deny` applied directly — enumerating names closes what we thought of; the class closes the rest.

## Design decision: the exit code for "one file could not be scanned" stays **1**, not 2

Issue #542's body says the escaping traceback exits 1 "for the one class of failure that means 'could not scan' (2)", but its own Fix section says to *report rather than escape*. Those pull in opposite directions, so this plan resolves it explicitly.

`scripts/check_tag_t3.py:604-608` defines the contract: **0** clean, **1** violations found, **2** the gate could not run. The three cannot-scan conditions that already exist — `_UNPARSEABLE_MESSAGE` (`SyntaxError`), `_UNDECODABLE_MESSAGE` (latin-1 source), `_UNREADABLE_MESSAGE` (`OSError`) — are all reported as **violations (rc=1)**, deliberately: a file the gate cannot read is a file the gate is not gating, which fails closed and blocks the PR. **2** is reserved for "the gate never gated *anything*" (empty scan root, census floor below `_MIN_SCANNED_FILES`).

One unscannable file out of 332 is not "the gate gated nothing" — it is one reported violation among 331 successful scans. Making it rc=2 would be inconsistent with the three existing arms and would tell an operator the gate never ran when it did.

**So the real defects #542 fixes are:** (a) the traceback, (b) the *unreported* failure, and (c) **the aborted scan loop** — every file after the offending one going unscanned, silently. (c) is the paper-gate shape and is the substantive fix. rc stays 1, but now *intentionally*, with a message, and with the scan complete.

## Design decision: where the "pin the pin" recursion bottoms out

The brief asks that #541's pin not itself be silently deletable. A test file can always be deleted, so the recursion has to bottom out; pretending otherwise with a "pin that pins the pin" would be theatre. **This plan bottoms it out by layering two independent enforcement mechanisms per surface, so that no single deletion disarms either surface:**

| Surface | Layer 1 — runtime floor (reds inside an already-required check) | Layer 2 — static pin (names the surface) |
| --- | --- | --- |
| **A.** the `check_tag_t3` coverage-gate step in `ci.yml` | `--min-gates` raised 20 → 26 so the count tracks reality; deleting the step drops it to 25 and reds `test_runner_still_finds_the_gates_in_each_ci_job` in the required `Python (lint, types, unit)` check | Task 2's named pin — asserts a `coverage report` gate whose `--include` is exactly `scripts/check_tag_t3.py` at `--fail-under=100` |
| **B.** the `plugins` argument in both invocations | `_MIN_SCANNED_FILES` raised 250 → 300; dropping `plugins` yields 293 < 300 → the gate itself exits **2**, loudly, inside the required `tag(T3) grep gate` check | Task 2's named pin — asserts both `Makefile` and `pr-validate-python.yml` pass `src/alfred` **and** `plugins` |

Layer 1 for surface B is the stronger half and is the direct application of the #518 lesson recorded in `procedural_518_t3_runtime_invariant`: **a runtime invariant beats a static detector.** Deleting `plugins` from an invocation no longer needs a *test* to notice — the gate refuses to run.

Deleting Task 2's pin file leaves both runtime floors intact. Defeating a runtime floor requires editing a documented constant whose comment states the derivation — a deliberate, reviewable diff, not a silent one-line deletion. That is the bottom, and it is stated here rather than hidden.

```python
"""The gate surfaces #537 landed must not be silently removable (#541).

#537 added two things a future edit can delete in one line, with nothing
saying a word:

1. the ``check_tag_t3 detector 100% line+branch coverage`` step in
   ``ci.yml`` — deleting it left 25 gates against a ``--min-gates 20``
   floor, so every check stayed green;
2. the ``plugins`` argument to ``scripts/check_tag_t3.py`` in the
   ``Makefile`` and ``pr-validate-python.yml`` — dropping it left 293
   scanned files against a ``_MIN_SCANNED_FILES = 250`` floor, so 39
   first-party plugin files (including
   ``plugins/alfred_discord/inbound_emitter.py``, a real ingestion
   boundary) silently stopped being gated.

Both floors were raised to track reality in the same PR, so each surface
already reds at RUNTIME. These cases are the second, independent layer:
they name the surface, so swapping one gate for another — which keeps the
count intact — is still caught.

**Two oracles per surface, deliberately.** Each surface is asserted once
against the raw file text and once against the parsed/derived view. A pin
that reused only the implementation's own predicate would pass through the
very drift it exists to catch — the repo has been bitten by a tautological
oracle twice (see the #537 review). The two views must agree.
"""

from __future__ import annotations

import importlib.util
import re
from pathlib import Path
from typing import Any

import pytest
import yaml

_REPO_ROOT: Path = Path(__file__).resolve().parents[3]
_CI_WORKFLOW: Path = _REPO_ROOT / ".github" / "workflows" / "ci.yml"
_PR_VALIDATE: Path = _REPO_ROOT / ".github" / "workflows" / "pr-validate-python.yml"
_MAKEFILE: Path = _REPO_ROOT / "Makefile"
_RUNNER: Path = _REPO_ROOT / "scripts" / "run_coverage_gates.py"

# Every coverage gate that must exist in ci.yml's `python` job BY NAME, as
# (include-spec, threshold). The count floor in test_coverage_gate_runner.py
# catches a net loss; this catches a swap, which keeps the count intact.
_REQUIRED_COVERAGE_GATES: tuple[tuple[str, int], ...] = (
    ("scripts/check_tag_t3.py", 100),
)

# Every scan root `check_tag_t3.py` must be invoked with, at every call site.
# `plugins` is here because #537 added it and #541 is the bill for it being
# droppable: `src/alfred` alone is 293 files, which clears any floor set for
# the combined 332.
_REQUIRED_SCAN_ROOTS: tuple[str, ...] = ("src/alfred", "plugins")


def _load_runner() -> Any:
    """Import ``scripts/run_coverage_gates.py`` — a script, not a package."""
    spec = importlib.util.spec_from_file_location("run_coverage_gates", _RUNNER)
    assert spec is not None and spec.loader is not None
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module


@pytest.fixture(scope="module")
def ci_workflow() -> dict[str, Any]:
    return yaml.safe_load(_CI_WORKFLOW.read_text(encoding="utf-8"))


# ── Surface A: the ci.yml coverage-gate step ──────────────────────────────


@pytest.mark.parametrize(("include", "threshold"), _REQUIRED_COVERAGE_GATES)
def test_the_gate_is_visible_to_the_runner(
    ci_workflow: dict[str, Any], include: str, threshold: int
) -> None:
    """Oracle 1 — the DERIVED view: `run_coverage_gates.py` extracts it.

    This is what `make check` actually runs, so a gate the runner cannot see
    is a gate that does not run locally no matter what the YAML says.
    """
    gates = _load_runner()._iter_gates(ci_workflow, "python")
    matching = [g for g in gates if g.include == include]
    assert matching, (
        f"no coverage gate with --include='{include}' in ci.yml's `python` job. "
        f"#537 added it and #541 exists because deleting it was silent. "
        f"Found includes: {sorted(g.include for g in gates)}"
    )
    assert [g.threshold for g in matching] == [threshold], (
        f"the --include='{include}' gate must stay at --fail-under={threshold}; "
        f"got {[g.threshold for g in matching]}"
    )
```

- [ ] **Step 5: Write the census test**

Create `tests/unit/meta/test_scripts_coverage_census.py`:

```python
"""Every `scripts/*.py` must be gated at 100% or explicitly omitted (#543).

#537 added `--cov=scripts` so `check_tag_t3.py` could carry a 100% gate.
That pulled all seven scripts into the coverage dataset and gated exactly
one — `run_coverage_gates.py` at 50% and `check_strict_declarations.py` at
0%, both of them gate-enforcing code. The whole-tree floor is 75%, and
scripts/ is a small enough slice that a new file landing at 0% moves it by
less than the floor's headroom. So nothing would say a word.

This is the #423 mechanism: gate on the ALLOW-LIST, not the calendar. A new
`scripts/*.py` fails here until someone classifies it — either it earns a
100% gate in ci.yml, or it is named in pyproject's `omit` with a reason.
There is no third state where it silently joins the floor at 0%.
"""

from __future__ import annotations

import importlib.util
import tomllib
from pathlib import Path
from typing import Any

import yaml

_REPO_ROOT: Path = Path(__file__).resolve().parents[3]
_CI_WORKFLOW: Path = _REPO_ROOT / ".github" / "workflows" / "ci.yml"
_PYPROJECT: Path = _REPO_ROOT / "pyproject.toml"
_RUNNER: Path = _REPO_ROOT / "scripts" / "run_coverage_gates.py"


def _gated_script_paths() -> set[str]:
    """Scripts carrying a coverage gate of ANY threshold, derived from ci.yml.

    Deliberately not `threshold == 100`. The point of the census is that every
    script is *classified*, and a ratchet (e.g. `validate_devin_wiki.py` sits
    at a measured 94%) is a legitimate classification. Requiring 100 here would
    make the only two options "100% or invisible", which pushes borderline
    scripts into `omit` — the opposite of what #543 wants.
    """
    spec = importlib.util.spec_from_file_location("run_coverage_gates", _RUNNER)
    assert spec is not None and spec.loader is not None
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    workflow = yaml.safe_load(_CI_WORKFLOW.read_text(encoding="utf-8"))
    return {
        path
        for gate in module._iter_gates(workflow, "python")
        for path in gate.paths
        if path.startswith("scripts/")
    }


def _omitted_script_paths() -> set[str]:
    config: dict[str, Any] = tomllib.loads(_PYPROJECT.read_text(encoding="utf-8"))
    omit = config["tool"]["coverage"]["run"]["omit"]
    return {entry for entry in omit if entry.startswith("scripts/")}


def _measured_script_paths() -> set[str]:
    """Every tracked `.py` under `scripts/` — what `--cov=scripts` measures."""
    return {
        str(p.relative_to(_REPO_ROOT))
        for p in (_REPO_ROOT / "scripts").rglob("*.py")
        if "__pycache__" not in p.parts and "vendor" not in p.parts
    }


def test_every_script_is_either_gated_or_explicitly_omitted() -> None:
    """The #423 rule. A new script has no silent third state."""
    unclassified = _measured_script_paths() - _gated_script_paths() - _omitted_script_paths()
    assert not unclassified, (
        f"these scripts/ files are measured by `--cov=scripts` but are neither "
        f"gated in ci.yml nor omitted in pyproject.toml: {sorted(unclassified)}. "
        f"Give each one a coverage gate, or add it to [tool.coverage.run] omit "
        f"with a stated reason. Leaving it unclassified lets it join the 75% "
        f"whole-tree floor at 0% with nothing saying a word (#543, #423)."
    )


def test_the_two_classifications_do_not_overlap() -> None:
    """A file cannot be both gated and omitted — `omit` wins, so the gate would
    silently measure nothing. That is a paper gate with extra steps."""
    both = _gated_script_paths() & _omitted_script_paths()
    assert not both, (
        f"{sorted(both)} are both gated in ci.yml and omitted in pyproject.toml. "
        f"`omit` wins, so those gates measure an empty set and pass vacuously."
    )


def test_the_census_is_not_vacuous() -> None:
    """Anti-vacuity floor: if any of the three sets came back empty, the two
    assertions above would pass while checking nothing."""
    assert _measured_script_paths(), "no scripts/*.py found — the census is empty"
    assert _gated_script_paths(), "no scripts/ coverage gates found in ci.yml"
    assert _omitted_script_paths(), "no scripts/ omit entries found in pyproject.toml"


def test_the_gate_enforcing_scripts_are_gated_not_omitted() -> None:
    """The two #543 named these specifically. Naming them here means moving
    either into `omit` is a failing edit, not a quiet one."""
    gated = _gated_script_paths()
    for script in ("scripts/run_coverage_gates.py", "scripts/check_strict_declarations.py"):
        assert script in gated, (
            f"{script} is gate-enforcing code and must carry its own 100% gate "
            f"(#543); found gated scripts: {sorted(gated)}"
        )
```
