### #542 claims — BOTH confirmed. v1 was wrong to refute one

v1 claimed `RecursionError` was unreachable, based on probes run on one local interpreter. **That claim is withdrawn (arch-001).** The variable is not the source shape — it is the **interpreter build**:

| Build (both report version 3.14.6) | `"x = " + "+".join(["1"]*50000)` |
| --- | --- |
| Homebrew CPython, `Clang 21` | **parses fine** |
| uv / proto standalone CPython, `Clang 22.1.3` | **`RecursionError: Stack overflow (used 8144 kB) during compilation`**, 3/3 deterministic, reproduces through the real `_scan_text` seam |

CPython 3.14's stack guard trips on **actual C-stack bytes consumed**, not the `sys.setrecursionlimit` counter, so identical source and identical version can disagree across builds. **CI provisions Python with `uv python install 3.14`** (`ci.yml:124,834,952,1155,1625`) — the standalone family — so **`RecursionError` is live in CI.**

Confirmed on **both** builds, so these are portable:

| Input | Result |
| --- | --- |
| `"not " * 20000 + "x"` (also `-`-chains, ternary chains, lambda nests, `**` chains) | `MemoryError: Parser stack overflowed` |
| `"(" * 200000 …` | `SyntaxError: too many nested parentheses` — already handled |
| `Path("foo\x00bar.py").read_text()` | `ValueError: embedded null byte` — **not** an `OSError` |
| `ast.parse("x = 1\x00\n")` | `SyntaxError`, `lineno=None` — handled by the existing `or 1` |

**Consequences.** The *fix* is unchanged and now doubly justified: `except Exception` catches `MemoryError` and `RecursionError` alike. What changes is (a) no comment, commit message or PR text may claim unreachability, and (b) a `RecursionError`-specific regression test would be **non-portable** — it raises on the standalone build and returns cleanly on Homebrew. Task 4 therefore uses a **build-agnostic** parametrised case (`_scan_text` must never raise, for any shape) with an anti-vacuity floor requiring at least one shape to actually trip the arm on the running build.

**Lesson recorded:** a probe on one interpreter does not establish a property of "CPython 3.14.6". Name the build.

## Design decision: how each surface resists silent removal

v1 claimed two layers per surface. Review found **both blind to the same bypass**: flipping a gate step's `if:` to `false` disarms it while every pin stays green and the runner still counts 26 (test-001) — the repo's own #514 shape. v1 also mis-described Layer 1A: `run_coverage_gates.py` is invoked by **no workflow**, so the `--min-gates` floor is a *local* signal; what enforces it in CI is the unit test asserting the count, inside the required `Python (lint, types, unit)` check (arch-002).

Corrected model:

| Surface | Enforcement |
| --- | --- |
| **A.** the `check_tag_t3` coverage-gate step in `ci.yml` | (1) gate-count floor raised 20 → 26 so a net removal reds `test_runner_still_finds_the_gates_in_each_ci_job` **in CI**; (2) named pin on the include+threshold, so a *swap* is caught; (3) **`if:`-condition pin** (new), so disarming the step via its guard is caught |
| **B.** the `plugins` scan root | **The script owns the root list.** `_DEFAULT_SCAN_ROOTS = ("src/alfred", "plugins")` moves into `check_tag_t3.py`; both call sites invoke it with **no arguments**. Dropping a root is no longer an edit to a Makefile line — it requires editing a constant in a 100%-covered, mypy+pyright-checked script, pinned by a test that does not monkeypatch it |

**Surface B's v1 mechanism is withdrawn.** v1 raised `_MIN_SCANNED_FILES` 250 → 300. Review measured its margin as **7 files, not 32**: `src/alfred` is 293, so once it grows past 300 it clears the floor alone and dropping `plugins` stops being detected. That tree grew +19 files in 23 days — roughly **8 days** of working life (sec-002, test-006, arch-004). The floor also failed to be an invariant at all: four shapes clear it while gating a subset, including `src/alfred src/alfred`, which double-counts (sec-001). And it broke two pre-existing tests the plan never named (rev-002, arch-003, ops-002, sec-003, test-004 — five reviewers).

Making the script own the roots is strictly better: immune to tree growth, has no margin to erode, and needs no floor change. **It is NOT free, and v3's claim that it "breaks no existing test" was false** — corrected on execution. The runtime invariant that makes the ownership real (rather than a lexical pin a line-continuation defeats) refuses a partial in-repo directory scan, and **11 pre-existing tests across 2 files asserted exactly that shape**. Narrowing the invariant to in-repo directory arguments cleared 1 of the 11 (`test_a_symlinked_package_directory_does_not_hide_its_subtree`, an out-of-repo `tmp_path` fixture); the remaining 10 were asserting the OLD contract and were updated deliberately, each named in the Task 3 report. Measured: `tests/unit` 7018 passed / 1 pre-existing macOS flake before, 7027 passed / 0 failed after.

`_MIN_SCANNED_FILES` **stays at 250**, keeping its original single purpose: catching a run from the wrong working directory.

## The mutation-test harness (read before any mutation step)

v1's mutation blocks were **Critical-broken** (rev-001): each opened with `set -e` and then ran a pytest whose non-zero exit is the *expected* result, so `set -e` killed the block at the first mutation and **no restore ever ran**. Executed verbatim, v1 left `ci.yml` with the gate swapped out and left the #542 fix reverted — and the next step told the implementer to commit.

Every mutation step below uses this helper. Write it once, source it in each step. It never uses `set -e`, restores unconditionally on every path, and asserts the tree is clean afterwards.

**Portability matters here and was verified.** A first draft used `trap … RETURN`, which is a bashism: **zsh rejects it** (`trap: undefined signal: RETURN`) and the mutated file survives — reproducing the very Critical this helper exists to fix, on the shell this repo's sessions actually use. The version below restores on an explicit line rather than via a RETURN trap, keeps `INT`/`TERM` for interrupt safety (both portable), and was executed in **bash and zsh**, on both the mutation-applied and bad-anchor paths, leaving the file `ORIGINAL` in all four runs.

**v2's helper was also wrong, in three further ways review measured.** It had no green baseline, so a mutation aimed at an already-failing test reported "killed" — that is what hid the append-vs-replace gap. It scored **any** non-zero rc as a kill, but pytest uses `2` = interrupted, `3` = internal error, `4` = usage error, `5` = **no tests collected**; a mutation that breaks collection, or a `-k` filter matching nothing, therefore reported "guard works". Devops proved the point by running a **no-op mutation and getting three false kills** (rc 5/4/1). And its variables leaked into the caller's shell.

Only **rc == 1** ("tests ran and failed") is evidence. Everything else is a harness error and must say so.

```bash
mkdir -p /tmp/gate-mut
cat > /tmp/gate-mut/mutate.sh <<'HELPER'
# mutate <label> <file> <python-mutation-source> <pytest-args...>
# Green-baseline -> mutate -> run -> ALWAYS restore.
# ONLY rc==1 counts as a kill. Verified on bash and zsh (`local` works in both).
mutate() {
  local label="$1" file="$2" mutation="$3"; shift 3
  local bak rc
  bak="/tmp/gate-mut/$(echo "$file" | tr '/' '_').bak"

  # 1. GREEN BASELINE. A mutation aimed at an already-red test proves nothing —
  #    this is exactly how v2's M9 reported a kill against a permanently-failing
  #    fixture. Refuse to proceed rather than emit a false positive.
  uv run pytest "$@" -q >/tmp/gate-mut/baseline.txt 2>&1
  if [ $? -ne 0 ]; then
    echo "  $label: BASELINE NOT GREEN — target test already fails. Mutation would prove nothing."
    tail -20 /tmp/gate-mut/baseline.txt
    return 1
  fi

  cp "$file" "$bak"
  trap 'cp "$bak" "$file"; echo "  interrupted — $file restored"; exit 130' INT TERM
  if ! python3 -c "$mutation"; then
    cp "$bak" "$file"; trap - INT TERM
    echo "  $label: MUTATION DID NOT APPLY (anchor text changed?) — investigate"
    return 1
  fi

  uv run pytest "$@" -q >/tmp/gate-mut/out.txt 2>&1
  rc=$?
  cp "$bak" "$file"
  trap - INT TERM

  # 2. ONLY rc==1 is a kill. pytest: 2=interrupted, 3=internal, 4=usage,
  #    5=NO TESTS COLLECTED. A mutation that breaks collection or a -k filter
  #    matching nothing exits non-zero while testing nothing.
  case "$rc" in
    1) echo "  $label: killed (rc=1) — guard works" ;;
    0) echo "  $label: *** SURVIVED (rc=0) — the guard does NOT work. STOP. ***"
       tail -20 /tmp/gate-mut/out.txt; return 1 ;;
    *) echo "  $label: *** HARNESS ERROR (rc=$rc) — the mutation proved NOTHING. ***"
       tail -20 /tmp/gate-mut/out.txt; return 1 ;;
  esac
  return 0
}
HELPER
echo "helper written"
```

Record the **observed rc per mutation** in the PR's mutation matrix, not a bare "killed".

After every mutation step, prove the tree is pristine:

```bash
if [ -z "$(git status --porcelain)" ]; then echo CLEAN; else echo DIRTY; git status --porcelain; fi
```

**Not `git status --porcelain && echo "CLEAN"`.** Porcelain exits 0 whether the tree is
dirty or clean, so the `&& echo` fires unconditionally and prints `CLEAN` over the top of
a tree the mutation harness left mutated — a vacuous check on the check. The `[ -z ... ]`
form branches on porcelain's OUTPUT, which is the thing that carries the answer.

**If any mutation reports `SURVIVED`, that guard does not work — fix it before committing.**

```python
* DELETE it -> 25 gates against a `--min-gates 20` floor: silent. Closed by

* SWAP it for an unrelated gate -> count still 26: silent. Closed here by

  the pin + runner cases pass. That is the #514 shape — a required check

# (include-spec, threshold). The count floor catches a net loss; this catches

_REQUIRED_COVERAGE_GATES: tuple[tuple[str, int], ...] = (
    ("scripts/check_tag_t3.py", 100),

# `if:` conditions a gate step may carry, NORMALISED. `steps.check.outputs.has_py`
# is the `python` job's fail-closed source probe (id `check`, hardened in #517).
#
# Normalisation matters: `if: ${{ steps.check.outputs.has_py == 'true' }}` is the
# SAME condition and GitHub accepts both spellings, but raw string equality reds
# on it. Strip a surrounding `${{ … }}` and collapse whitespace before comparing —
# normalise, do not widen the set, or a genuinely different guard slips in.
_APPROVED_GATE_CONDITIONS: frozenset[str] = frozenset(
    {"steps.check.outputs.has_py == 'true'"}
)

# Keys a pinned gate step may carry — DEFAULT-DENY, not an enumerated blocklist.
#
# `if: false` is only ONE of at least four ways to disarm the step, and the other
# three were measured leaving every pin green: job- or step-level
# `continue-on-error: true`, and `|| true` / `; exit 0` inside the `run:` block.
# Enumerating the disarm shapes closes the ones we thought of — the #518 mistake.
# So: allow a known-good key set and refuse anything else, whatever it is called.
_ALLOWED_GATE_STEP_KEYS: frozenset[str] = frozenset({"name", "if", "run"})

# Shell fragments that neutralise a non-zero exit inside `run:`.
_EXIT_NEUTRALISERS: tuple[str, ...] = ("|| true", "|| :", "; exit 0", "set +e")

_GATE_STEP_NAMES: tuple[str, ...] = ("check_tag_t3 detector 100% line+branch coverage",)

def _load_runner() -> Any:
    """Import ``scripts/run_coverage_gates.py`` — a script, not a package."""
    spec = importlib.util.spec_from_file_location("run_coverage_gates", _RUNNER)
    assert spec is not None and spec.loader is not None
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module

@pytest.fixture(scope="module")

def _python_job_steps(workflow: dict[str, Any]) -> list[dict[str, Any]]:
    return [s for s in workflow["jobs"]["python"]["steps"] if isinstance(s, dict)]

@pytest.mark.parametrize(("include", "threshold"), _REQUIRED_COVERAGE_GATES)

def _normalise_condition(raw: object) -> str:
    """Strip a surrounding ``${{ … }}`` and collapse whitespace.

    GitHub accepts ``if: X`` and ``if: ${{ X }}`` as the same condition. Raw
    equality reds on the second, so normalise rather than widening the approved
    set — widening would admit conditions that are genuinely different.
    """
    text = " ".join(str(raw).split())
    if text.startswith("${{") and text.endswith("}}"):
        text = " ".join(text[3:-2].split())
    return text

@pytest.mark.parametrize("step_name", _GATE_STEP_NAMES)
def test_a_gate_step_cannot_be_disarmed(
    ci_workflow: dict[str, Any], step_name: str
) -> None:
    """DEFAULT-DENY the ways a gate step can be made not to gate.

    `_iter_gates` is a static parse: it counts a step whose `if:` is literally
    `false`, so the count floor and the name pins are both blind to disarming.
    But `if:` is only one of at least FOUR shapes, all measured during plan
    review leaving every pin green:

        if: false                     -> the step never runs
        continue-on-error: true       -> it runs, fails, and the job passes
        run: ... || true              -> the command's failure is swallowed
        run: ...; exit 0              -> same, via the exit code

    Enumerating those four would close the four we thought of. So instead:
    allow a known key set and refuse anything outside it, plus refuse
    exit-neutralising shell inside `run:`. A new disarm mechanism has to get
    past an allow-list, not past a blocklist (#518's lesson, #514's shape).
    """
    steps = [s for s in _python_job_steps(ci_workflow) if s.get("name") == step_name]
    assert steps, f"ci.yml's `python` job has no step named {step_name!r}"

    job = ci_workflow["jobs"]["python"]
    assert not job.get("continue-on-error"), (
        "the `python` job carries continue-on-error, which makes EVERY coverage "
        "gate in it advisory while every pin here stays green"
    )

    for step in steps:
        unexpected = set(step) - _ALLOWED_GATE_STEP_KEYS
        assert not unexpected, (
            f"step {step_name!r} carries unexpected key(s) {sorted(unexpected)}. "
            f"Only {sorted(_ALLOWED_GATE_STEP_KEYS)} are allowed on a gate step: "
            f"anything else (continue-on-error, timeout-minutes, env, …) may "
            f"change whether a failure blocks the merge. If the new key is "
            f"legitimate, add it here deliberately (#541)."
        )
        condition = _normalise_condition(step.get("if", ""))
        assert condition in _APPROVED_GATE_CONDITIONS, (
            f"step {step_name!r} has if: {condition!r} (normalised), not in the "
            f"approved set {sorted(_APPROVED_GATE_CONDITIONS)}."
        )
        run = str(step.get("run", ""))
        for fragment in _EXIT_NEUTRALISERS:
            assert fragment not in run, (
                f"step {step_name!r} run: contains {fragment!r}, which swallows "
                f"the gate's non-zero exit — the gate would report green while "
                f"the coverage threshold was breached (#541)."
            )

def test_the_approved_condition_is_a_real_probe(ci_workflow: dict[str, Any]) -> None:
    """Anti-vacuity: the approved `if:` must reference a step that EXISTS.

    Pinning a condition that names a nonexistent step id would pin a guard
    that is always false — the failure the pin exists to prevent, reproduced
    inside the pin.
    """
    ids = {s.get("id") for s in _python_job_steps(ci_workflow) if s.get("id")}
    assert "check" in ids, (
        "ci.yml's `python` job has no step with id `check`; the approved gate "
        f"condition references it. Step ids present: {sorted(i for i in ids if i)}"
    )

def test_the_two_gate_oracles_agree(ci_workflow: dict[str, Any]) -> None:
    """Anti-vacuity floor: both views must SEE something, and agree."""
    derived = {g.include for g in _load_runner()._iter_gates(ci_workflow, "python")}

    assert derived, "the runner extracted NO gates — this pin is gating nothing"
    assert raw, "the raw view found NO --include= specs — this pin is gating nothing"
    assert derived <= raw, f"runner saw gates absent from the raw text: {derived - raw}"
```

```python
_RUNNER: Path = _REPO_ROOT / "scripts" / "run_coverage_gates.py"

def _gated_script_paths() -> set[str]:
    """Scripts carrying a coverage gate of ANY threshold, derived from ci.yml.

    Deliberately not `threshold == 100`. The census exists to ensure every
    script is CLASSIFIED; a ratchet is a legitimate classification. Requiring
    100 would leave only "100% or invisible", pushing borderline scripts into
    `omit` — the opposite of what #543 wants.
    """
    spec = importlib.util.spec_from_file_location("run_coverage_gates", _RUNNER)
    assert spec is not None and spec.loader is not None
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    workflow = yaml.safe_load(_CI_WORKFLOW.read_text(encoding="utf-8"))
    return {
        path
        for gate in module._iter_gates(workflow, "python")
        for path in gate.paths
        if path.startswith("scripts/")
    }

def _omitted_script_paths() -> set[str]:
    config: dict[str, Any] = tomllib.loads(_PYPROJECT.read_text(encoding="utf-8"))
    omit = config["tool"]["coverage"]["run"]["omit"]
    return {entry for entry in omit if entry.startswith("scripts/")}

def _is_censused(path: Path) -> bool:
    """Whether a `scripts/` file is subject to the census.

    Split out of `_measured_script_paths` so the exemption rule can be asserted
    against SYNTHETIC paths. A filter only ever run over the tree as it stands
    is untestable in the direction that matters — does it exempt MORE than it
    should?

    ANCHORED at `scripts/vendor/`, not "any path component named `vendor`".
    v2's `"vendor" not in p.parts` exempts a `vendor` directory anywhere under
    `scripts/`, while the `scripts/vendor/**` omit entry does not stop coverage
    measuring one — so `scripts/tools/vendor/mod.py` would be measured,
    unclassified, and invisible to the census. That is the exact hole this file
    exists to close, reproduced inside it. Dormant today (`scripts/vendor/`
    holds one JSON file and no `.py`) — fixed anyway, because "dormant" is a
    property of the tree, not of the rule.
    """
    return "__pycache__" not in path.parts and not path.is_relative_to(_VENDOR_DIR)

def _measured_script_paths() -> set[str]:
    """Every `.py` under `scripts/` — what `--cov=scripts` measures.

    `as_posix()` is load-bearing: `str(PurePath)` renders with `os.sep`, so on
    the Windows unit leg every path would carry backslashes while the gated
    and omitted sets come from YAML/TOML with forward slashes. The mismatch
    would be total and the census would report every script unclassified.
    """
    return {
        p.relative_to(_REPO_ROOT).as_posix()
        for p in _SCRIPTS_DIR.rglob("*.py")
        if _is_censused(p)
    }

def test_every_script_is_either_gated_or_explicitly_omitted() -> None:
    """The #423 rule. A new script has no silent third state."""
    unclassified = _measured_script_paths() - _gated_script_paths() - _omitted_script_paths()
    assert not unclassified, (
        f"these scripts/ files are measured by `--cov=scripts` but are neither "
        f"gated in ci.yml nor omitted in pyproject.toml: {sorted(unclassified)}. "
        f"Give each one a coverage gate, or add it to [tool.coverage.run] omit "
        f"with a stated reason. Leaving it unclassified lets it join the 75% "
        f"whole-tree floor at 0% with nothing saying a word (#543, #423)."
    )

def test_the_two_classifications_do_not_overlap() -> None:
    """A file cannot be both gated and omitted — `omit` wins, so the gate would
    measure an empty set and pass vacuously. A paper gate with extra steps."""
    both = _gated_script_paths() & _omitted_script_paths()
    assert not both, (
        f"{sorted(both)} are both gated in ci.yml and omitted in pyproject.toml. "
        f"`omit` wins, so those gates measure nothing and pass vacuously."
    )

def test_the_census_is_not_vacuous() -> None:
    """Anti-vacuity floor: an empty set on any side makes the two assertions
    above pass while checking nothing."""
    assert _measured_script_paths(), "no scripts/*.py found — the census is empty"
    assert _gated_script_paths(), "no scripts/ coverage gates found in ci.yml"
    assert _omitted_script_paths(), "no scripts/ omit entries found in pyproject.toml"

def test_the_gate_enforcing_scripts_are_gated_not_omitted() -> None:
    """Naming these means moving either into `omit` is a failing edit."""
    gated = _gated_script_paths()
    for script in ("scripts/run_coverage_gates.py", "scripts/check_strict_declarations.py"):
        assert script in gated, (
            f"{script} is gate-enforcing code and must carry its own gate "
            f"(#543); found gated scripts: {sorted(gated)}"
        )

def test_the_vendor_exemption_names_the_same_root_as_the_omit_entry() -> None:
    """The census's one exemption and coverage's `omit` must describe ONE set.

    Two sides, two mechanisms: coverage stops MEASURING `scripts/vendor/**`,
    `_is_censused` stops the census CLASSIFYING it. Different roots means the
    difference between them is measured-but-unclassified — the state this file
    refuses. Pinned by root rather than by calling into `coverage.files`, whose
    matcher class was renamed within the versions this repo has installed
    (`FnmatchMatcher` -> `GlobMatcher`); a pin on a private API that breaks on
    upgrade teaches people to delete pins.
    """
    vendor_entries = {entry for entry in _omitted_script_paths() if "vendor" in entry}
    assert vendor_entries == {_VENDOR_OMIT_ENTRY}
    assert _VENDOR_OMIT_ENTRY.removesuffix("/**") == _VENDOR_DIR.relative_to(_REPO_ROOT).as_posix()

def test_the_vendor_exemption_is_anchored_rather_than_name_based() -> None:
    """Exempt `scripts/vendor/` at ANY depth — and nothing else called `vendor`."""
    assert not _is_censused(_VENDOR_DIR / "mod.py")
    assert not _is_censused(_VENDOR_DIR / "pkg" / "mod.py")
    assert _is_censused(_SCRIPTS_DIR / "tools" / "vendor" / "mod.py")
    assert _is_censused(_SCRIPTS_DIR / "some_new_script.py")
```
